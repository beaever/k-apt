# K-apt 아스콘 입찰 정보 수집기

[K-apt(공동주택관리정보시스템)](https://www.k-apt.go.kr)에서 아스콘(아스팔트 콘크리트) 공사 낙찰 공고를 검색하고,
공고문(첨부파일 또는 외부 원문)에서 자본금·실적·공법번호 같은 비정형 요건을 자동으로 추출해
엑셀 파일로 내려받는 웹 서비스입니다.

## 주요 기능

- 지역(서울/인천/경기), 검색어, 검색 기간(직접 지정, 최대 1년)으로 낙찰 공고 검색
- 검색 결과 페이지네이션을 전부 순회해 조건에 맞는 **모든** 공고 수집 (건수 제한 없음)
- 공고 상세페이지 접속 후 아파트명/세대수/낙찰업체/낙찰금액 등 자동 추출
- 첨부된 입찰공고문(HWP/HWPX/PDF) 자동 다운로드 후 텍스트 추출
- K-apt 자체 첨부파일이 없는 공고는 "해당 공고 가기"를 통해 외부 대행 사이트(a2p.kr, kg2b.com 등)의
  원문 공고서까지 따라가서 확보
- 공고문 텍스트에서 자본금 / 실적 / 공법(특허)번호 요건을 정규식으로 추출
- 값을 찾지 못한 경우 빈 칸이 아니라 **왜 못 찾았는지 구체적인 사유**를 표시
  (첨부파일 없음 / 다운로드 실패 사유 / 지원하지 않는 파일 형식 / 문서에 해당 문구 없음 등)
- 5개 공고를 동시에 처리하는 병렬 크롤링 (K-apt 상세·첨부는 브라우저 대신 HTTP로 직접 받고, 공고문 분석은 별도 프로세스에서 진행)
- 결과를 정상 / 확인 필요(노란 줄) / 수집 실패(빨간 줄) 3단계로 구분 + 값마다 근거 문장 표시 + 엑셀 다운로드

## 기술 스택

| 영역 | 기술 |
|---|---|
| 백엔드 | Python, FastAPI, Playwright(Chromium), pdfplumber, pyhwp, BeautifulSoup4, openpyxl |
| 프런트엔드 | Next.js(App Router), React, TypeScript, Tailwind CSS |

인증/결제 기능은 포함하지 않습니다.

## 프로젝트 구조

```
kapt-asphalt-collector/
  launcher.py              # 더블클릭 실행기: 최신 main 적용 -> Node.js·부품 설치 -> 서버 실행 -> 브라우저 열기
  start.bat / start.command # Windows / macOS 더블클릭 파일 (Python을 받아 launcher.py 호출)
  backend/

      crawler/
        step1_search.py    # K-apt 접속 → 지역/검색어/기간 필터 → 목록 수집(페이지네이션 전체)
        step2_download.py  # 상세페이지 접속 → 첨부파일(또는 외부 원문) 다운로드
      parser/
        step3_parse.py     # PDF/HWP/HWPX 텍스트 추출 + 자본금/실적/공법번호 정규식 파싱
      export/
        step4_excel.py     # 결과 병합 후 엑셀(.xlsx) 생성, 상태별 색상 표시
      storage/              # 요청(job)별 다운로드 파일 및 생성된 엑셀 (git 미포함)
    requirements.txt
    tests/
      test_parsing.py      # 파싱 로직 자체 점검 스크립트
      test_launcher.py     # 실행기 업데이트 로직 자체 점검 스크립트
  frontend/
    app/page.tsx            # 검색 폼 + 진행 상태 + 결과 표 + 엑셀 다운로드 버튼
```

## 내 컴퓨터에서 사용하기 (비개발자용 안내)

개발 지식이 없어도 쓸 수 있습니다. 프로그램을 따로 설치하거나 터미널을 열 필요 없이, **압축을 풀고 더블클릭**하면 됩니다.

### 1단계. 파일 받기 (처음 한 번만)

1. https://github.com/beaever/k-apt/archive/refs/heads/main.zip 을 눌러 내려받습니다. (로그인 불필요)
2. 받은 ZIP 파일의 **압축을 풀고**, 폴더를 바탕화면처럼 찾기 쉬운 곳에 둡니다.

### 2단계. 더블클릭으로 실행하기 (쓸 때마다)

폴더 안의 파일을 더블클릭합니다. 바로가기(별칭)를 바탕화면에 만들어 두면 더 편합니다.

- **Windows**: `start.bat`
- **macOS**: `start.command`

새 창이 열리고 아래 순서로 자동 진행된 뒤 **브라우저에 검색 화면이 열립니다**.

1. 최신 버전이 있으면 적용합니다.
2. 처음이거나 부품이 바뀌었으면 필요한 프로그램과 부품을 내려받습니다. (처음에는 수 분 소요, 인터넷 필요)
3. 프로그램을 켜고 브라우저를 엽니다.

**다 쓰면 그 창을 닫으면 프로그램도 꺼집니다.** 사용 중에는 창을 닫지 마세요.

> 처음 실행할 때 보안 경고가 나올 수 있습니다.
> - Windows "PC 보호" 창: **추가 정보** → **실행**
> - macOS "열 수 없음" 창: **시스템 설정 → 개인정보 보호 및 보안** 맨 아래의 **그래도 열기**
>
> 내려받은 Python과 Node.js는 폴더 안 `runtime`에만 저장되며, PC에 설치되지 않습니다. 지우고 싶으면 폴더째 삭제하면 됩니다.

### 3단계. 사용하기

1. 지역(서울/인천/경기)을 체크합니다.
2. 검색어를 입력합니다. (예: "아스콘")
3. 기간을 고릅니다. 빠른 선택(1주일/1개월/1년) 버튼을 눌러도 됩니다. (최대 1년)
4. **검색 시작**을 누릅니다.
   - 진행 상황("12/40건")이 표시됩니다. 1개월치 기준 수 분, 1년치는 수십 분 걸릴 수 있습니다.
   - 진행 중에는 브라우저 탭을 닫지 마세요. (실행 창도 켜둔 채로)
5. 끝나면 결과 표와 정상 / 확인 필요 / 수집 실패 건수가 나오고, **엑셀 다운로드** 버튼으로 파일을 받을 수 있습니다.
   (브라우저의 기본 다운로드 폴더에 저장됩니다)

### 결과 보는 법

| 보이는 값 | 뜻 | 할 일 |
|---|---|---|
| 상태 **정상** | 모든 칸이 공고문에서 확인된 값이고 의심할 신호도 없음 | 그대로 사용 |
| 자본금·실적 **제한없음**, 공법번호 **미적용** | 공고문을 읽었고 그 요건 자체가 없음 (예: 특허 요건이 없는 공고). 못 읽었거나 불명확한 경우에는 쓰지 않음 | 그대로 사용 |
| 상태 **확인 필요** (노란 줄) | 공고문은 읽었지만 값을 못 찾았거나 오인 가능성이 있음. 상태 칸에 이유가 적혀 있음 | 자본금/실적/공법번호 칸에 마우스를 올려 근거 문장 확인 |
| 상태 **수집 실패** (빨간 줄) | 페이지/첨부파일을 못 받았거나 공고문을 읽지 못함 | 아파트명 링크(엑셀) / "원문 보기"(화면)로 원문 확인 |

자본금은 `5억`, 실적은 `500세대 5건`(세대 조건이 없으면 `5년 5건`)처럼 핵심 수치만 표시됩니다.
어느 문장·파일에서 뽑았는지는 **엑셀 셀 메모**(셀 모서리의 빨간 삼각형, 마우스를 올리면 보임)와
화면 표의 **점선 밑줄 칸**에 마우스를 올리면 볼 수 있습니다.

### 새 버전 받기

**따로 할 일이 없습니다.** 실행 파일을 더블클릭할 때마다 최신 `main`을 확인해 자동으로 적용합니다.
이미 켜 둔 상태라면 창을 닫고 다시 실행하면 됩니다. 인터넷이 끊겼거나 업데이트에 실패하면 지금 버전으로 그대로 실행됩니다.

새 버전을 확인할 때는 **기간 1개월**로 검색해 아래 항목을 봅니다.

| 확인할 것 | 정상이라면 |
|---|---|
| 결과 표 위 건수 | "정상 / 확인 필요 / 수집 실패" 3가지로 나뉘어 표시됨 |
| 결과 표·엑셀의 공고일자 | 오래된 날짜가 위, 최신 날짜가 아래로 정렬됨 |
| 줄 색상 | 확인 필요는 노란 줄, 수집 실패는 빨간 줄 |
| 자본금·실적 칸 | `5억`, `500세대 5건` 처럼 핵심 수치만 표시됨 |
| 자본금 칸에 마우스 올리기 | "근거: (원문 문장) / 파일: (파일명)" 이 뜸 |
| 엑셀 다운로드 후 공고일자·아파트명 | 날짜만(`2026-09-03`), "(입대의)" 없이 표시됨 |
| 엑셀 자본금 칸 모서리 빨간 삼각형 | 마우스를 올리면 근거 문장 메모가 보임 |
| 엑셀 노란/빨간 줄의 아파트명 | 누르면 K-apt 원문 페이지가 열림 |

### 자주 묻는 문제

| 증상 | 해결 |
|---|---|
| "Python을 내려받지 못했습니다" / "Node.js를 내려받지 못했습니다" | 인터넷 연결을 확인한 뒤 다시 실행. 회사망이면 보안 정책에서 막혔을 수 있으니 담당자에게 문의 |
| 설치 중 `[notice] A new release of pip is available` | 오류 아님. 무시하면 됨 |
| "다른 프로그램이 ○○번 포트를 쓰고 있습니다" | 다른 실행 창이 남아 있는지 확인해 닫거나 PC 재시작 |
| 화면에서 "다른 수집 작업이 진행 중입니다" | 한 번에 하나만 수집 가능. 진행 중인 작업이 끝날 때까지 기다리기 |
| 화면에서 "수집 서버에 연결하지 못했어요" / 아무 반응 없음 | 실행 창이 켜져 있는지 확인. 닫혔다면 다시 더블클릭 |
| 화면에서 "K-apt 접속이 제한됐을 수 있어요" | 짧은 시간에 많이 수집해 K-apt가 접속을 막은 상태. 수집은 자동으로 멈춤. 브라우저로 K-apt에 들어가 안내 팝업에서 제한을 해제한 뒤 잠시 후 다시 시도 |
| 오류가 나서 원인을 모르겠음 | 창 내용을 캡처하고 `.launcher` 폴더의 `backend.log`, `frontend.log` 를 담당자에게 전달 |
| 화면에서 "수집 중 오류가 발생했습니다" | K-apt 사이트가 일시적으로 느린 경우가 많음. 잠시 후 다시 시도 |
| 전에 받은 엑셀을 다시 받으려는데 안 됨 | 결과 파일은 24시간 뒤 자동 삭제됨. 다시 검색 (30일 안에 받은 공고는 저장본을 써서 빠르게 끝남) |

### 개발자용: 새 버전 배포

**`main`에 머지하면 사용자가 다음에 실행할 때 자동으로 적용됩니다.** 검증 단계 없이 바로 전달되므로, 문제가 있으면 `main`에서 되돌리는 커밋을 올리면 다음 실행 때 복구됩니다.
테스트 단계에 맞춘 방식이라, 정식 운영으로 넘어갈 때는 Release 등 검증된 버전만 전달하도록 바꾸는 것을 권합니다.

- `start.bat` / `start.command`의 주소와 해시가 Python 버전을, `launcher.py`의 `NODE_VERSION` / `NODE_BUILDS`가 Node.js 버전을 고정합니다.
- 실행기가 받은 Python·Node.js는 `runtime/`, 상태와 로그는 `.launcher/`에 있습니다.
- `.git` 폴더가 있는 개발 폴더에서는 업데이트를 건너뛰어 작업 중인 코드를 덮어쓰지 않습니다.
- 업데이트 로직 점검: `python3 backend/tests/test_launcher.py`

### 개발자용 실행 요약

```bash
# backend
cd backend && python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt && playwright install chromium
uvicorn app.main:app --host 127.0.0.1 --port 8420

# frontend (백엔드 주소가 기본값과 다르면 .env.example -> .env.local 복사 후 NEXT_PUBLIC_API_BASE 수정)
cd frontend && npm install && npm run dev
```

HWP 텍스트 추출은 `pyhwp` 라이브러리를 프로세스 안에서 직접 호출하고, HWPX는 표준 라이브러리(zip/XML)로 읽습니다.

엑셀/결과 표의 컬럼: 공고일자 / 아파트명 / 공사명 / 세대수 / 자본금 / 실적 / 공법번호 /
낙찰방법 / 낙찰업체 / 낙찰금액 / 상태 (화면 표에는 "공고 링크" 컬럼이 추가로 있음)

**상태 판정 기준**: 크롤링 도중 예외가 났는지만 보지 않고, **10개 데이터 컬럼이 전부 확인된
값인지**와 값을 의심할 신호가 있는지로 정상 / 확인 필요 / 수집 실패를 가립니다. 자본금/실적/공법번호는 키워드가 있는 줄이라도 아래 값이 있어야
"확인된 값"으로 인정합니다.

| 컬럼 | 인정 조건 | 조건 미달 시 |
|---|---|---|
| 자본금 | 금액(예: 5억, 500,000,000원) | `[확인 필요] 원문 문장` |
| 실적 | 건수(N건/회) 또는 금액 | `[확인 필요] 원문 문장` |
| 공법번호 | 특허·실용신안 등록번호(10-/20-XXXXXXX), 문서 전체에서 탐색 | `[확인 필요] 공법 문장` |

- 공고문 전체에 관련 문구(자본금 / 실적·최근 N년간 / 특허·공법·신기술·실용신안)가 전혀 없으면
  자본금·실적은 **"제한없음"**, 공법번호는 **"미적용"**으로 채우고 정상으로 봅니다. 단, 텍스트를 뽑지 못한 첨부파일(스캔 PDF 등)이 하나라도
  있으면 단정하지 않고 확인 필요로 둡니다.
- 값을 찾았더라도 다음 경우는 **확인 필요**로 돌립니다: 공고문 안에 자본금 금액이 서로 다르게 여러 개 있음,
  자본금이 0.1억~50억 / 실적이 1~30건 범위를 벗어남, 요건이 아니라 제출서류 문장("실적증명서 1부")에서 뽑힘.
- 공고문 자체를 받지 못했거나 텍스트를 하나도 뽑지 못하면 **수집 실패**입니다.
- 글자가 이미지로만 된 스캔 PDF는 글자 인식(OCR)으로 앞 2쪽까지 읽습니다. 오독 가능성이 있어 값을 찾아도 항상
  **확인 필요**로 표시합니다. 처음 쓸 때 모델을 내려받으므로(약 55MB) 인터넷 연결이 필요하고, 모델을 받지 못하면 수집 실패로 남습니다.
- 따라서 **"정상" 행은 원문을 열지 않아도 되고, "확인 필요" 행은 근거 문장만, "수집 실패" 행만 원문을 확인**하면 됩니다.
  (실제 공고 44건(2026년 6~9월) 검증: 정상 40건, 확인 필요 4건은 모두 원문 표현이 모호한 경우, 수집 실패 0건)

**자동 추출은 100%가 아닙니다.** 정규식 파싱은 문서 표현이 특이하거나(스캔/벡터 이미지
PDF처럼 텍스트 자체를 못 뽑는 경우 포함) 예상 밖 레이아웃이면 실패할 수 있고, 이는
OCR이나 LLM을 붙여도 근본적으로 해결되지 않습니다(참고: OCR/LLM은 발견율을 높일 순
있지만 오인식·환각 위험이 있어 숫자값 신뢰도 면에서 더 위험할 수 있음). 그래서 "확인 필요/수집 실패"
행은 값을 억지로 채우지 않고 근거 문장과 원문 상세페이지 바로가기를 제공합니다 —
이 행들만 직접 확인하는 것을 전제로 설계되었습니다.

## 동작 원리 (4단계)

1. **검색(step1_search.py)** — Playwright로 K-apt 메인 페이지 진입 후 메뉴 링크 클릭으로
   "사업자 선정(경쟁입찰) 결과 공개" 페이지 접속 (직접 URL 접근은 세션 미인증 에러 발생).
   지역/검색어/기간 필터 적용 후 전체 페이지를 순회하며 공고 목록 수집.
2. **상세/다운로드(step2_download.py)** — 공고별 상세페이지에서 정보 추출 및 첨부파일 다운로드.
   K-apt 상세페이지와 첨부파일은 브라우저 화면 없이 HTTP로 받고, 첨부 목록 API로 받을 파일 수를 먼저 확인해
   일부만 받은 경우를 실패 사유로 남김. K-apt 자체 첨부파일이 없으면 "해당 공고 가기" 버튼으로 외부 대행
   사이트에 진입해 원문을 확보. 동수·세대수가 0이거나 뒤바뀐 등록 오류는 보정하거나 빈칸(확인 필요)으로 둠.
3. **파싱(step3_parse.py)** — 다운로드한 PDF/HWP/HWPX에서 텍스트를 추출하고, 자본금/실적/공법(특허)번호가
   적힌 줄을 정규식으로 찾아냄. 못 찾으면 사유를 값 대신 기록.
4. **엑셀 출력(step4_excel.py)** — 위 결과를 병합해 `.xlsx`로 저장, 확인 필요는 노란색·수집 실패는 빨간색으로 강조하고 값마다 근거 문장을 셀 메모로 첨부.

## 배포 (무료, 1~2인 테스트 규모)

계정 생성/저장소 연결/배포 버튼 클릭은 직접 하셔야 합니다. 아래는 그 준비물입니다.

### 백엔드 → Render (무료 웹서비스)

1. [Render](https://render.com)에서 GitHub 저장소(`beaever/k-apt`) 연결 후 "New Web Service" 생성
   - 이 저장소 루트의 `render.yaml`을 인식시키면(Blueprint) 자동으로 아래 설정이 적용됩니다.
   - 수동으로 만드는 경우: Root Directory `backend`, Runtime `Docker`, Instance Type `Free`
2. 환경변수 `CORS_ORIGINS`에 배포된 프런트엔드 주소(예: `https://your-app.vercel.app`)를 입력
3. 배포 완료 후 나오는 주소(`https://xxxx.onrender.com`)를 프런트엔드 환경변수에 사용

`DETAIL_CONCURRENCY`는 무료 티어의 적은 메모리(크로미움 여러 개 동시 실행 시 부족할 수 있음)를 고려해
`render.yaml`에서 기본 2로 낮춰뒀습니다. 공고문 분석용 프로세스 수 `PARSE_PROCESSES`(로컬 기본: CPU 수, 최대 4)도
프로세스당 약 100MB를 써서 1로 낮춰뒀습니다. 필요하면 Render 대시보드에서 조정하세요.

**무료 티어 제약**: 15분간 요청이 없으면 인스턴스가 슬립되고, 다음 요청 시 재기동에 수십 초가 걸립니다.
1~2인이 가끔 쓰는 용도로는 문제없지만 상시 빠른 응답이 필요하면 유료 플랜이 필요합니다.

### 프런트엔드 → Vercel (무료)

1. [Vercel](https://vercel.com)에서 저장소 연결, Root Directory를 `frontend`로 지정
2. 환경변수 `NEXT_PUBLIC_API_BASE`에 Render 백엔드 주소 입력
3. 배포하면 `https://your-app.vercel.app` 형태의 주소가 생성됨

### 알려진 배포 한계

- Render 무료 인스턴스의 로컬 디스크는 재시작 시 초기화됩니다. "검색 → 엑셀 다운로드"를 같은 세션에서
  바로 이어서 하면 문제없지만, 시간이 많이 지난 뒤 다운로드를 시도하면 파일이 사라졌을 수 있습니다.
- 수집은 백그라운드 작업으로 실행되고 프런트엔드가 진행 상태를 폴링하므로, 검색 범위가 커서 오래 걸려도
  요청이 끊기지 않습니다. 단, 진행 상태는 서버 메모리에 있어 도중에 서버가 재시작되면 작업이 사라집니다.
- 메모리 보호를 위해 수집 작업은 서버당 1개만 동시에 실행됩니다(진행 중이면 새 요청은 거절).
- 24시간이 지난 작업 폴더(엑셀)는 새 작업이 시작될 때 자동 삭제됩니다.
- 첨부파일을 빠짐없이 받은 공고는 상세정보·첨부파일을 `storage/cache-v1/공고번호/`에 30일간 저장해, 다시 수집할 때
  K-apt에 접속하지 않고 재사용합니다. 공고문 분석은 매번 새로 하므로 분석 규칙을 고치면 저장본에도 바로 반영됩니다.
  상세정보 추출 방식(`step2_download.py`)을 바꾸면 `main.py`의 `CACHE_DIR` 버전을 올려 옛 저장본을 버리세요.
- 수집 도중 상세페이지 대신 다른 페이지가 오면 접속 제한으로 보고 남은 공고를 요청하지 않고 멈춥니다.

## 알려진 제한사항

- 상세페이지/첨부파일 구조가 K-apt 자체 전자입찰, a2p.kr, kg2b.com 등 대행사별로 달라
  확인된 레이아웃 외의 새로운 형태가 나오면 파싱이 실패할 수 있습니다(이 경우 실패 사유가 표시됩니다).
- `.hwpx` 등 HWP/PDF 이외의 첨부파일 형식은 텍스트 추출을 지원하지 않습니다.
- 요건 값은 정규식/키워드 기반 추출이므로 문서 표현이 특이한 경우 놓칠 수 있습니다.
- K-apt 사이트 구조가 변경되면 selector를 다시 확인해야 합니다.
